# Prompt 100 / BWP-18 — Signed audit attestations and public verification

## Implemented functionality and changed files

- Added strict public health claims, canonical domain-separated Ed25519 signing bytes, public-only trusted-key records, signature envelopes, revocation snapshots, verification results, and immutable lifecycle event contracts. The signed claims bind the digest of the complete private `AuditAttestationDocument` and an allowlisted health projection. Signing rejects a health report ID that does not match the report reference in the attestation document.
- Added Ed25519 signing and verification with canonical base64 encoding, key ID and algorithm binding, trust-key validity checks, optional private-document digest verification, expiry, revocation, supersession, and separate signature-valid/current-endorsement results. Current endorsement requires both a fresh trusted-key snapshot and a fresh lifecycle snapshot. Missing or stale state cannot become a current endorsement. Development keys are never endorsements.
- Added lifecycle reduction for draft → review_required → approved → signed → published, plus expiry, revocation and correction successors. It checks distinct owner/reviewer/signer/publisher roles, evidence digests, chronological event chains, legal transitions, and prevents publishing after expiry or silently renewing an attestation.
- Added tenant-scoped append/read methods over the existing immutable `audit_event` table. Appends lock the private attestation row, check sequence/digest links, make exact retries idempotent, bind publication/expiry to the signed document expiry, and require a persisted same-tenant successor with a matching digest for correction events. These methods were not exercised against PostgreSQL.
- Added a local `pcb audit verify-attestation` path that accepts only a public attestation file and public trust store; it performs no API request. Added a no-store public API route that accepts only a strict public projection and returns verified status. With no injected public store or trust configuration it fails closed.
- Added the attestation lookup/detail pages and certificate-style view. Invalid signatures withhold all signed claim values. The page shows scope/missingness, key and revocation status, model-agnostic versus context-bound scope, expiry, and limitations. A fresh superseded state links to its corrected successor. Copy says the signature is not certification, unseen-data assurance, model-training proof, or independent timestamp proof; it also distinguishes publishing an aggregate report from publishing task text.
- Changed files: `packages/core/src/polycodebench_core/audit_attestations.py`, `packages/services/src/polycodebench_services/audit_attestations.py`, `packages/persistence/src/polycodebench_persistence/benchmark_audit.py`, `packages/api/src/polycodebench_api/{app.py,audit_cli.py,benchmark_audit_routes.py,context.py}`, `packages/api/openapi.v1.json`, `apps/web/package.json`, `apps/web/playwright.prompt100.config.ts`, `apps/web/src/app/audit-attestations/`, `apps/web/src/components/audit-attestation.tsx`, `apps/web/src/components/public-ui.tsx`, `apps/web/src/lib/{audit-attestations.ts,public-api.ts,generated-public-api.ts}`, `apps/web/src/app/globals.css`, `apps/web/tests/e2e/{prompt100.spec.ts,launch-prompt100-api.py}`, `tests/test_audit_attestations.py`, and `tests/test_benchmark_audit_api.py`.

## Decisions or specification discrepancies recorded

- `ADDENDUM-DECISION-45`: the public signature commits to the canonical private attestation digest and a separately allowlisted health projection. It proves signed-byte integrity only; it does not prove the private source evidence or timestamp independently.
- `ADDENDUM-DECISION-46`: current endorsement requires both a fresh trust-store snapshot and a fresh lifecycle/revocation snapshot. A valid signature with either state missing or stale remains qualified and cannot be shown as a current endorsement.
- `ADDENDUM-DECISION-47`: a superseding attestation must be stored first and linked by `supersedes_id`; the append-only event binds its ID and digest. Aggregate report publication remains separate from task-text publication.
- No new specification discrepancy was found. The existing §1 source-list discrepancy remains: the addendum says five source Markdown files were read but names/hashes three.
